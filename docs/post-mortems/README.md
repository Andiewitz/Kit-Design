# Post-Mortems

Write a post-mortem after any incident that affects users, corrupts or loses data, causes a security exposure, or requires an out-of-band fix. Reviews are blameless and focus on system behavior.

## Naming

`YYYY-MM-DD-short-slug.md`

## Expectations

- Publish a draft within two business days of resolution.
- Record a factual timeline with timestamps and timezone.
- Separate contributing factors from the root cause.
- Give every action item an owner and a due date.
- Link related issues, plans, and commits.

Start from [`_template.md`](_template.md).
